# 路线编辑器 V2 Graph 交互规则文档

本文档记录当前已经确定的所有交互规则、视觉规则、菜单规则、快捷键规则、选择规则、删除规则、底部工具栏规则、说明面板规则。

本文档只记录已经确定的内容，不引入新的设计决策。

---

# 1. 基础数据对象

路线编辑器基于 V2 graph。

V2 graph 中主要编辑对象分为两类：

```text
node：节点
edge：路线 / 连线 / 线段
```

其中：

```text
edge.from -> edge.to
```

表示该条路线的方向。

---

# 2. 编辑模式下的默认视觉状态

## 2.1 路线默认视觉状态

在编辑模式下：

- 路线仍然保持彩色路线显示。
- 路线颜色沿用当前已有的路线颜色逻辑。
- 编辑模式不会把路线改成单色。
- 编辑模式下依旧可以看到路线本身的颜色。

---

## 2.2 节点默认视觉状态

在编辑模式下：

- 在路线的每一个节点位置显示一个圆形节点。
- 节点默认样式为：

```text
白底
黑边
圆形
```

---

# 3. 节点 hover / 选中视觉状态

## 3.1 节点 hover 状态

当鼠标移动到节点上时：

- 该节点放大一圈。
- 放大幅度约为原尺寸的 `25%`。
- hover 放大只表示鼠标当前指向该节点。
- hover 不改变该节点是否被选中。

---

## 3.2 节点选中状态

当节点被选中时：

- 节点加金黄色阴影。
- 阴影从节点重心向外扩散。
- 阴影表现为渐变式外扩光晕。
- 选中状态不通过修改节点黑边为金边来实现。

采用金黄色阴影的原因：

- 后续节点可能不再是白底黑边圆点。
- 后续节点可能改成其他颜色。
- 后续节点可能改成特殊 SVG 图形。
- 使用外部金黄色阴影可以覆盖在各种节点样式外层。
- 这样后续扩展节点样式时，不需要重新为每一种节点样式写选中边框。

---

# 4. 路线 hover / 选中视觉状态

## 4.1 路线默认状态

路线默认显示为彩色路线。

---

## 4.2 路线 hover 状态

当前已有逻辑是：

- 鼠标放到路线附近时；
- 路线两侧会显示白色、半透明、加粗的路线阴影。

该逻辑保留。

也就是说 hover 路线时：

```text
彩色路线本体仍然显示
路线两侧出现白色半透明加粗线
```

---

## 4.3 路线选中状态

当路线被选中时：

- 复用当前 hover 的加粗路线阴影逻辑。
- 但是颜色从白色改成金色 / 黄色。
- 表现为路线两侧有金色半透明加粗路线阴影。

也就是说：

```text
hover 路线：白色半透明加粗路线阴影
选中路线：金色半透明加粗路线阴影
```

---

# 5. 路线方向箭头显示规则

## 5.1 编辑模式下显示方向箭头

编辑模式下，路线需要显示方向箭头。

方向箭头表示：

```text
edge.from -> edge.to
```

---

## 5.2 平时箭头状态

在编辑模式下，每条 edge 平时都显示方向箭头。

平时箭头状态为：

- 小箭头。
- 颜色较淡。
- 不抢占主要视觉。
- 用来让用户能看出每条路线的大致方向。

---

## 5.3 hover / 选中时箭头状态

当路线被 hover 或选中时：

- 该路线的方向箭头变大。
- 该路线的方向箭头变亮。
- 用于强调当前路线方向。

---

## 5.4 展示模式下箭头逻辑

展示模式下：

- 保持当前已有箭头逻辑。
- 不强制按照编辑模式每条 edge 显示小箭头。
- 展示模式主要避免视觉噪音。

---

# 6. 连接模式视觉反馈

连接模式指：

```text
从一个节点开始，连接到另一个节点
```

也就是用户在节点菜单中点击“开始连接”之后，进入的临时状态。

---

## 6.1 连接模式开始

当用户对某个节点点击“开始连接”后：

- 该节点成为源节点。
- 进入连接模式。
- 源节点显示选中状态。
- 源节点带金黄色阴影。

---

## 6.2 实时虚线

连接模式下：

- 从源节点到当前鼠标位置画一条实时跟随的虚线。
- 虚线随着鼠标移动实时更新。
- 虚线只表示临时连接预览。
- 虚线不代表已经创建 edge。
- 只有用户点击目标节点后，才真正创建连接。

---

## 6.3 鼠标旁提示文字

连接模式下：

- 鼠标旁显示提示文字。
- 提示文字跟随鼠标移动。
- 提示内容类似：

```text
点击目标节点完成连接
```

提示文字用于明确告诉用户：

```text
当前正在等待用户点击另一个节点
```

---

## 6.4 目标节点 hover 反馈

连接模式下，当鼠标 hover 到其他可作为目标的节点时：

- 目标节点仍然执行普通 hover 放大效果。
- 同时额外显示绿色阴影。
- 绿色阴影表示：

```text
当前节点可以作为连接目标
```

---

## 6.5 连接完成

连接模式下，当用户点击目标节点后：

- 创建一条从源节点到目标节点的 edge。
- 连接方向为：

```text
源节点 -> 目标节点
```

- 实时虚线消失。
- 鼠标旁提示文字消失。
- 目标节点绿色阴影消失。
- 退出连接模式。

---

## 6.6 连接取消

连接模式下，以下操作取消连接：

- 点击地图空白处。
- 按 Esc。

取消连接后：

- 不创建 edge。
- 实时虚线消失。
- 鼠标旁提示文字消失。
- 源节点连接模式高亮取消。
- 退出连接模式。

---

# 7. 快捷键 / 浏览器默认行为拦截

## 7.1 地图编辑模式下需要拦截的默认行为

在地图编辑模式下，需要统一拦截部分网页 / Leaflet 默认行为，避免和编辑器操作冲突。

需要拦截：

```text
Shift + 拖拽
Tab
地图上的鼠标右键菜单
其他后续需要追加的冲突快捷键
```

---

## 7.2 Shift + 拖拽

默认 Leaflet 行为中：

```text
Shift + 鼠标拖拽
```

可能触发框选缩放。

在路线编辑模式下：

- 需要屏蔽这个默认行为。
- Shift + 拖拽不再用于 Leaflet 框选缩放。
- Shift + 拖拽用于路线编辑器的连续选择 / 拖选。

---

## 7.3 Tab

Tab 默认可能切换网页焦点。

在地图编辑模式下：

- 当地图容器处于操作上下文中时，需要拦截 Tab。
- 防止用户编辑时焦点跳到页面其他元素。

---

## 7.4 地图右键

地图上的浏览器默认右键菜单需要拦截。

在路线编辑模式下：

- 右键用于路线编辑器的上下文菜单。
- 不弹浏览器默认右键菜单。

---

## 7.5 拦截范围

快捷键和鼠标默认行为拦截范围：

- 仅限地图编辑相关区域。
- 仅限地图容器获得焦点或处于编辑上下文时。
- 不应影响页面其他普通输入区域的正常操作。

---

# 8. 选择模型基础规则

## 8.1 不区分“单选模式”和“多选模式”

系统不单独维护：

```text
单选模式
多选模式
```

系统只维护：

```text
当前选中的元素集合
当前选中类型
```

---

## 8.2 当前选中类型

当前选中类型只能是以下之一：

```text
none
node
edge
```

含义：

```text
none：当前没有选中任何东西
node：当前选中集合里是节点
edge：当前选中集合里是路线
```

---

## 8.3 选中数量决定表现

根据当前选中集合数量决定表现：

```text
选中 0 个：无选中
选中 1 个：表现为单选
选中多个：表现为多选
```

---

## 8.4 Shift 的含义

Shift 不代表一定进入“多选状态”。

Shift 的含义是：

```text
修改当前选择集合
```

具体包括：

- 追加选择。
- 取消选择。
- 拖选。
- 连续选择。

如果按住 Shift 只选中了一个元素，那么结果上仍然是单选。

---

# 9. 普通左键点击选择规则

## 9.1 不按 Shift 点击 node / edge

不按 Shift 时，左键点击任意 node 或 edge：

- 清空旧选择。
- 选中当前点击的元素。
- 当前选中类型切换为该元素类型。

也就是说：

```text
普通左键点击永远是重新选择
```

---

## 9.2 普通点击 edge

不按 Shift，左键点击某条 edge：

- 清空之前选中的 node 或 edge。
- 当前只选中这条 edge。
- 当前选中类型变成 edge。

---

## 9.3 普通点击 node

不按 Shift，左键点击某个 node：

- 清空之前选中的 node 或 edge。
- 当前只选中这个 node。
- 当前选中类型变成 node。

---

# 10. Shift 点击选择规则

## 10.1 当前没有任何选中时，Shift 点击元素

当前选中集合为空时：

```text
Shift + 左键点击 node
```

结果：

- 选中该 node。
- 当前选中类型设为 node。

当前选中集合为空时：

```text
Shift + 左键点击 edge
```

结果：

- 选中该 edge。
- 当前选中类型设为 edge。

也就是说：

```text
Shift 也可以作为第一次选择的起点
```

---

## 10.2 Shift 点击同类型未选中元素

当前选中类型为 node 时：

```text
Shift + 点击未选中的 node
```

结果：

- 该 node 加入选中集合。

当前选中类型为 edge 时：

```text
Shift + 点击未选中的 edge
```

结果：

- 该 edge 加入选中集合。

---

## 10.3 Shift 点击同类型已选中元素

当前选中类型为 node 时：

```text
Shift + 点击已选中的 node
```

结果：

- 该 node 从选中集合中移除。
- 其他已选 node 保持选中。

当前选中类型为 edge 时：

```text
Shift + 点击已选中的 edge
```

结果：

- 该 edge 从选中集合中移除。
- 其他已选 edge 保持选中。

---

## 10.4 Shift 点击不同类型元素

为了防误操作，Shift 点击不同类型元素无效。

当前选中类型为 edge 时：

```text
Shift + 点击 node
```

结果：

- 不选中该 node。
- 不清空当前 edge 选择。
- 当前 edge 选择保持不变。

当前选中类型为 node 时：

```text
Shift + 点击 edge
```

结果：

- 不选中该 edge。
- 不清空当前 node 选择。
- 当前 node 选择保持不变。

原因：

- 用户在多选过程中可能误点到不同类型元素。
- 如果真的要切换选择类型，用户应该松开 Shift，用普通左键点击目标元素。

---

## 10.5 Shift 点击取消到只剩 1 个元素

如果 Shift 点击已选元素后，选中集合从多个变成一个：

- 当前仍然保留这个元素的选中。
- 结果表现为单选。
- 当前选中类型保持为该元素类型。

---

## 10.6 Shift 点击取消到 0 个元素

如果 Shift 点击已选元素后，选中集合为空：

- 清空选中集合。
- 当前选中类型变为 none。

---

# 11. 多选清空规则

## 11.1 不按 Shift 点击 graph 元素

当前选中多个元素时，不按 Shift 点击任意 node 或 edge：

- 清空当前多选。
- 选中被点击的那个元素。
- 当前选中类型切换为该元素类型。

适用于：

```text
点击已选中的元素
点击未选中的同类型元素
点击不同类型元素
```

---

## 11.2 点击地图空白处

点击地图空白处：

- 不清空多选。
- 不改变当前选中集合。
- 用户可以继续拖动地图或继续编辑。

---

## 11.3 点击地图自带大头针 / 装饰标记

点击地图本身自带的大头针、装饰标记、非 graph 编辑元素：

- 不清空多选。
- 不改变当前选中集合。

---

## 11.4 缩放地图

缩放地图：

- 不清空多选。
- 不改变当前选中集合。

---

## 11.5 Esc

按 Esc：

- 清空当前选择。
- 选中集合变为空。
- 当前选中类型变为 none。

Esc 也用于取消连接模式。

---

# 12. 右键菜单选择规则

## 12.1 右键点击已选元素

如果当前有选中集合，并且右键点击的是已选中的元素：

- 不清空选择。
- 弹出多选菜单。
- 菜单作用于当前全部选中集合。

例如：

```text
已选中 3 条 edge
右键点击其中一条已选 edge
```

结果：

- 弹出 edge 多选菜单。
- 操作对象是这 3 条 edge。

---

## 12.2 右键点击未选元素

如果当前有选中集合，但右键点击的是未选中的 node 或 edge：

- 清空当前选中集合。
- 选中右键点击的那个元素。
- 弹出该元素的单个右键菜单。

例如：

```text
已选中 3 条 edge
右键点击一个未选中的 node
```

结果：

- 清空 3 条 edge 的选择。
- 选中该 node。
- 弹出 node 单个菜单。

该规则参考 Word / 表格类软件习惯：

```text
如果已经多选了一些内容，但右键点到未选中的对象，
通常会切换到右键点击的对象，并对它弹出菜单。
```

---

## 12.3 右键点击地图空白处

右键点击地图空白处：

- 不弹浏览器默认菜单。
- 是否弹地图级菜单暂未定义。
- 当前规则中，不作为已确定功能。

---

# 13. Shift 拖选总规则

## 13.1 Shift 进入选择编辑状态

按住 Shift 时，用户处于选择编辑状态。

在该状态下：

- 可以 Shift + 单击 node / edge。
- 可以 Shift + 拖拽进行拖选。
- 可以追加选择。
- 可以取消选择。

---

## 13.2 Shift 拖选必须有明确起点

Shift + 拖选不能从空白处开始。

Shift 拖选必须从一个明确的 graph 元素开始：

```text
node
或
edge
```

如果从空白处开始拖：

- 不触发拖选。
- 不改变当前选择。

---

## 13.3 起点决定拖选类型

Shift 从 node 开始拖：

- 本次拖选类型锁定为 node。
- 本次拖选过程中只选择 node。
- 不选择 edge。

Shift 从 edge 开始拖：

- 本次拖选类型锁定为 edge。
- 本次拖选过程中只选择 edge。
- 不选择 node。

---

## 13.4 拖选命中范围

拖选时不要求鼠标精确压到 node 或 edge 上。

node 拖选：

- 鼠标靠近 node 到一定范围内即可认为刷到该 node。

edge 拖选：

- 鼠标靠近 edge 到一定范围内即可认为刷到该 edge。

也就是说：

```text
拖选不是要求精确点击，而是有命中范围的刷选
```

---

# 14. Shift 拖选 edge 规则

## 14.1 edge 拖选只选择 edge

Shift 从 edge 开始拖：

- 本次拖选只检测 edge。
- 不检测 node。
- 不会选中 node。

---

## 14.2 edge 拖选必须拓扑连续

Shift 从某条 edge 开始拖选后：

- 只能沿着与当前路径相邻的 edge 连续刷选。
- 鼠标突然跳到远处不相邻的 edge，不会选中它。
- 拖选必须沿路线拓扑连续前进。

---

## 14.3 Shift + 点击 edge 不要求连续

连续限制只适用于 Shift 拖选。

如果是：

```text
Shift + 点击 edge
```

则不要求这些 edge 拓扑连续。

也就是说：

```text
Shift + 拖选：必须连续
Shift + 点击：可以离散多选
```

---

## 14.4 edge 拖选前进时 toggle

edge 拖选过程中，当第一次刷到某条 edge 时：

如果该 edge 原本未选中：

```text
选中该 edge
```

如果该 edge 原本已选中：

```text
取消选中该 edge
```

---

## 14.5 拖选起点也参与 toggle

Shift 从某条 edge 开始拖选时：

- 起点 edge 也算被刷到。
- 起点 edge 也执行 toggle。

例如：

当前已选：

```text
A-B
B-C
```

Shift 从 `A-B` 开始拖，经过 `B-C`，再经过 `C-D`：

结果：

```text
A-B 被取消
B-C 被取消
C-D 被选中
```

---

## 14.6 edge 拖选维护本次拖选路径

Shift 拖选 edge 时，系统维护一条本次拖选路径。

例如：

```text
A-B -> B-C -> C-D
```

表示本次拖选路径依次刷过这些 edge。

---

## 14.7 edge 拖选支持路径尾部回退

如果本次拖选路径为：

```text
A-B -> B-C -> C-D
```

当鼠标从 `C-D` 往回靠近 `B-C`：

- 认为用户在回退。
- 撤销本次对 `C-D` 的选择变更。
- 当前拖选头部回到 `B-C`。

继续往回靠近 `A-B`：

- 撤销本次对 `B-C` 的选择变更。
- 当前拖选头部回到 `A-B`。

也就是说：

```text
往前刷：执行 toggle
往回刷：撤销最近一步 toggle
```

---

## 14.8 回退不是简单重复 toggle

拖选回退不是再次 toggle 同一个元素。

回退含义是：

```text
恢复到刷到该元素之前的选择状态
```

例如：

如果 `C-D` 在本次前进时从未选中变为选中，那么回退时它恢复为未选中。

如果 `C-D` 在本次前进时从已选中变为未选中，那么回退时它恢复为已选中。

---

## 14.9 回退后可以改走其他分支

如果路线结构为：

```text
A -> B -> C
     \
      -> D
```

本次拖选先走：

```text
A-B -> B-C
```

然后鼠标往回退到：

```text
A-B
```

此时 `B-C` 的本次选择变更被撤销。

然后鼠标靠近 `B-D`，允许路径变成：

```text
A-B -> B-D
```

也就是说：

```text
可以先走一个分支
可以回退到分叉前
可以改走另一个分支
```

---

## 14.10 edge 拖选遇到分叉

当 edge 拖选遇到分叉时：

```text
A -> B -> C
     \
      -> D
```

如果当前位置有多个相邻候选 edge：

- 不弹提示。
- 不暂停。
- 不要求用户额外点击。
- 在所有相邻候选 edge 中，选择距离鼠标当前位置最近的一条。

规则：

```text
鼠标靠近哪条分支，就沿哪条分支继续刷选
```

# 15. Shift 拖选 node 规则

## 15.1 node 拖选只选择 node

Shift 从 node 开始拖：

- 本次拖选只检测 node。
- 不检测 edge。
- 不会选中 edge。

---

## 15.2 node 的拓扑由连接的 edge 决定

node 本身没有独立路线方向。

node 拖选的拓扑连续性由它连接的 edge 决定。

例如：

```text
A -> B -> C -> E
     \
      -> D
```

在这个结构中：

- B 连接了多条路线。
- C 连接了两条路线。
- node 拖选时，必须沿着这些 edge 形成的拓扑路径移动。

---

## 15.3 node 拖选必须沿 edge 拓扑连续

Shift 从 node 开始拖选后：

- 只能沿着与当前 node 相连的 edge 前进到下一个 node。
- 不能凭空跳到远处不相连的 node。
- 拖选必须沿路线拓扑进行。

---

## 15.4 node 拖选命中范围

node 拖选时：

- 不要求鼠标准确压在 node 圆点上。
- 鼠标进入 node 附近一定范围即可认为刷到该 node。
- 该规则类似 edge 拖选的命中范围。

---

## 15.5 node 拖选前进时 toggle

node 拖选过程中，当第一次刷到某个 node 时：

如果该 node 原本未选中：

```text
选中该 node
```

如果该 node 原本已选中：

```text
取消选中该 node
```

---

## 15.6 拖选起点 node 也参与 toggle

Shift 从某个 node 开始拖选时：

- 起点 node 也算被刷到。
- 起点 node 也执行 toggle。

例如：

当前已选：

```text
A
B
```

Shift 从 A 开始拖，经过 B，再经过 C：

结果：

```text
A 被取消
B 被取消
C 被选中
```

最终只剩：

```text
C
```

---

## 15.7 node 拖选支持路径回退

node 拖选和 edge 拖选一样，支持路径回退。

当本次拖选路径为：

```text
A -> B -> C
```

如果鼠标从 C 往回靠近 B：

- 认为用户在回退。
- 撤销本次对 C 的选择变更。
- 当前拖选头部回到 B。

继续往回靠近 A：

- 撤销本次对 B 的选择变更。
- 当前拖选头部回到 A。

---

## 15.8 node 拖选遇到分叉

node 拖选遇到分叉时：

```text
A -> B -> C
     \
      -> D
```

如果从 A 拖到 B 附近，后续存在多个可前进 node：

- 不弹提示。
- 不暂停。
- 不要求用户点击确认。
- 根据鼠标更靠近哪条分支 / 哪个候选 node 来决定继续走哪边。

规则和 edge 拖选一致：

```text
鼠标靠近哪条拓扑分支，就沿哪条分支继续
```

---

## 15.9 node 拖选回退后可以改走其他分支

node 拖选可以：

- 沿一个分支前进。
- 回退到分叉前。
- 撤销原分支尾部的本次选择变更。
- 改走另一个分支。

---

## 15.10 孤立 node 不能被拖选选中

如果一个 node 没有任何 edge 相连：

```text
入度 = 0
出度 = 0
```

则该 node 是孤立 node。

孤立 node：

- 可以被普通左键点击选中。
- 可以被 Shift 单击选中。
- 不能被 Shift 拖选选中。

原因：

- 拖选要求沿路线拓扑进行。
- 孤立 node 没有任何连接路线。
- 它不具备拖选路径。

# 25. node 菜单删除点规则

## 25.1 单个 node 删除点

从 node 右键菜单点击：

```text
删除点
```

执行：

- 删除该 node。
- 删除所有与该 node 相连的 edge。
- 不做任何继承。
- 不自动连接它原来的上游和下游。

---

## 25.2 node 删除点不继承的原因

node 菜单中的删除点表示用户明确要删除这个点。

如果该点是分叉点或交汇点，自动继承会产生歧义。

所以 node 菜单删除点永远简单粗暴：

```text

```

# 26. edge 菜单删除连线规则

## 26.1 删除连线

从 edge 菜单点击：

```text
删除连线
```

执行：

- 删除该 edge。
- 不删除 edge.from 对应的 node。
- 不删除 edge.to 对应的 node。

---

## 26.2 删除连线不删除节点的原因

因为 node 可能：

- 是其他路线的交汇点。
- 是用户希望保留的标记点。
- 删除 edge 后仍然有意义。

所以删除 edge 默认只断开连接，不删除 node。

---

# 27. edge 菜单删除上 / 下一个节点规则

## 27.1 功能目的

该功能主要用于解决路线录制时的异常节点。

场景：

- 路线录制过程中坐标识别错误。
- 某个节点坐标突变。
- 节点从负数变成正数，或从正数变成负数。
- 结果某个点飞到地图外面。
- 用户看不到该节点。
- 用户够不到该节点。
- 用户无法直接点击该节点删除。

这时用户可以从还能看到的相邻 edge 出发，通过：

```text
删除上一个节点
删除下一个节点
```

来删除飞出去的异常节点。

---

## 27.2 上一个节点 / 下一个节点定义

当前 edge 为：

```text
A -> B
```

即：

```text
from = A
to = B
```

则：

```text
删除上一个节点 = 删除 A
删除下一个节点 = 删除 B
```

这里完全根据 edge 方向决定。

---

## 27.3 被删节点为 1 入 1 出时

如果被删除的节点满足：

```text
入度 = 1
出度 = 1
```

则认为它是普通链路中间点。

删除时执行继承合并。

例如：

```text
A -> B -> C
```

删除 B 后变成：

```text
A -> C
```

执行步骤：

- 删除 B。
- 删除 `A -> B`。
- 删除 `B -> C`。
- 新建 `A -> C`。

---

## 27.4 被删节点不是 1 入 1 出时

如果被删除节点存在分叉或合流：

```text
入度 > 1
或
出度 > 1
或
连接关系不满足恰好 1 入 1 出
```

则不继承。

执行：

- 删除该 node。
- 删除所有与该 node 相连的 edge。
- 不创建新的 edge。

---

## 27.5 分叉示例

例如：

```text
      <- F
     /
Z -> A -> B -> C -> E
     \
      -> D
```

删除 A 时：

- A 连接多条路线。
- A 不是 1 入 1 出。
- 不知道应该继承到哪个方向。
- 所以不继承。
- 删除 A 和所有与 A 相连的 edge。

---

## 27.6 普通链路示例

例如：

```text
A -> B -> C -> D
```

如果通过 edge 菜单删除 B：

- B 是 1 入 1 出。
- 执行继承。
- 路线变成：

```text
A -> C -> D
```

如果删除 C：

- C 是 1 入 1 出。
- 执行继承。
- 路线变成：

```text
A -> B -> D
```

---

## 27.7 中途方向不一致示例

例如：

```text
A -> B <- C -> D -> E
```

如果删除 C：

- 需要根据 C 的入度 / 出度判断。
- 如果 C 不是恰好 1 入 1 出的可继承普通点，则不继承。
- 删除 C 后路线会断开。
- 可能结果类似：

```text
A -> B
D -> E
```

核心原则：

```text
只有明确 1 入 1 出时才继承
有歧义就不继承
```

---

# 28. 多选删除规则

## 28.1 多选 node 删除

多选 node 删除时：

对每个被选中的 node：

- 删除该 node。
- 删除所有与该 node 相连的 edge。
- 不继承。
- 不自动合并上下游。

---

## 28.2 多选 edge 删除

多选 edge 删除时：

- 删除所有选中的 edge。
- 不删除任何 node。
- 不自动清理孤立 node。

---

# 29. 反转方向规则

## 29.1 单条 edge 反转

单条 edge 反转时：

```text
from 和 to 交换
```

例如：

```json
{ "from": "A", "to": "B" }
```

变成：

```json
{ "from": "B", "to": "A" }
```

---

## 29.2 多选 edge 反转

多选 edge 反转时：

- 对每条被选中的 edge 独立执行 from/to 交换。
- 不维护额外 path。
- 不尝试自动判断整条路线顺序。
- 不做“统一方向”。

---

## 29.3 暂不做统一方向

当前第一版不做：

```text
统一方向
以某个端点为起点统一方向
整段路线自动排序
```

原因：

- 统一方向需要判断所选 edge 是否构成连续链。
- 还需要决定起点。
- 分叉、合流时会有歧义。
- 当前只确定“反转方向”。

---

# 30. 预览模式

## 30.1 预览模式入口

预览模式位于底部悬浮工具栏。

表现为一个可勾选选项。

---

## 30.2 预览模式开启后

开启预览模式后：

- 当前仍处于路线编辑功能中。
- 不真正退出编辑。
- 只是暂时禁用编辑交互。
- 按路线完成后的效果预览显示。
- 用户不能编辑节点。
- 用户不能编辑 edge。
- 用户不能拖动节点。
- 用户不能插入节点。
- 用户不能删除节点或 edge。
- 用户不能进行连接操作。

---

## 30.3 预览模式关闭后

取消勾选后：

- 回到编辑状态。
- 恢复节点显示。
- 恢复 edge 方向箭头显示。
- 恢复选择、右键菜单、拖选、框选等编辑交互。

---

# 31. 模式和操作冲突规则

## 31.1 连接模式优先

当处于连接模式时：

- 普通选择操作暂停。
- Shift 拖选、Ctrl 框选不应抢占连接模式。
- Esc / 点击空白处取消连接。

## 31.2 预览模式禁用编辑

当预览模式开启时：

- 不执行选择。
- 不执行右键菜单编辑。
- 不执行拖选。
- 不执行框选。
- 不执行连接。
- 只展示路线预览效果。

---

## 31.3 Ctrl 框选优先于普通右键菜单

按住 Ctrl 时：

```text
Ctrl + 右键拖拽
```

用于框选路线。

如果用户想打开右键菜单：

- 必须松开 Ctrl。
- 再右键点击目标元素。

# 36. 使用场景示例

## 36.1 选择多条不相连路线

操作：

```text
Shift + 点击 edge1
Shift + 点击 edge2
Shift + 点击 edge3
```

结果：

- edge1、edge2、edge3 被选中。
- 它们可以不连续。
- 当前选中类型为 edge。

---

## 36.2 沿路线连续刷选路线

操作：

```text
Shift 按住
从 edge1 开始拖
沿 edge1 -> edge2 -> edge3 移动
```

结果：

- edge1、edge2、edge3 按经过顺序 toggle。
- 拖选必须沿拓扑连续。

---

## 36.3 多选时误点节点

当前已选多条 edge。

操作：

```text
Shift + 点击 node
```

结果：

- 无效。
- 当前 edge 选择不变。

原因：

- 防止误操作。
- 如果想切换到 node，应松开 Shift 再点击 node。

---

## 36.4 多选后右键未选元素

当前已选多条 edge。

操作：

```text
右键点击一个未选中的 node
```

结果：

- 清空 edge 多选。
- 选中该 node。
- 弹出 node 单个菜单。

---

## 36.5 删除飞到地图外的异常节点

路线录制异常，形成：

```text
正常路线 -> 飞出去的异常点 -> 后续正常路线
```

用户点不到异常点。

操作：

- 右键点击还能看到的相邻 edge。
- 根据方向选择：

```text
删除上一个节点
或
删除下一个节点
```

结果：

- 如果异常点是 1 入 1 出，则删除并继承。
- 如果异常点是分叉点，则删除该点和所有相连 edge，不继承。

---

## 36.6 预览编辑结果

操作：

- 在底部工具栏勾选预览模式。

结果：

- 暂时无法编辑。
- 以完成路线的效果展示。
- 取消勾选后恢复编辑。
