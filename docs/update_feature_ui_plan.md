# 更新功能与关于页链接改造计划（前端先行）

> 日期：2026-02-10  
> 状态：已确认（待实施）

## 1. 背景与目标

本次先做**前端流程与交互**，后续再补后端服务。

目标包括：

1. 修正 About 页外链：
   - GitHub：`https://github.com/guhuo-km/WutheringWaves-Navigator`
   - B站主页：`https://space.bilibili.com/1876277780`
2. 新增“检查更新”前端能力（可自动检查 + 手动检查）。
3. 若有新版本：
   - 显示更新弹窗（含更新内容）
   - 弹窗提供「关闭」「下载」按钮
   - 下载按钮跳转到：`https://wuwuddt.com`
4. 在 UI 中显示更新提示红点：
   - About 页「检查更新」按钮右上角红点
   - 侧边栏「关于」导航项右上角红点

## 2. 范围说明

### 本阶段（前端）

- 完成 UI、状态模型、交互逻辑、启动自动检查流程。
- 更新来源先使用前端可控 Provider（Mock/Static）。
- 预留后端接入接口，不实现真实服务器接口调用。

### 后续阶段（后端）

- 将 Provider 替换为真实服务器接口。
- 对接真实版本号、更新说明、下载地址等数据。

---

## 3. 功能设计

## 3.1 About 页链接

1. GitHub 按钮指向真实仓库。
2. 作者区域改为可点击 B站主页入口（而非纯 UID 文本）。

## 3.2 更新状态模型（前端内存态）

建议统一维护以下状态：

- `has_update: bool`
- `current_version: str`
- `latest_version: str`
- `release_notes: str`
- `download_url: str`（本阶段固定为 `https://wuwuddt.com`）
- `checked_at: datetime`

## 3.3 检查更新触发方式

1. **自动检查**：应用启动后自动检查一次（异步，不阻塞 UI）。
2. **手动检查**：用户点击 About 页「检查更新」按钮时触发检查。

## 3.4 有更新时的交互

1. 弹出更新说明对话框，显示：
   - 最新版本号
   - 更新内容（release notes）
2. 按钮：
   - `关闭`
   - `下载`（打开 `https://wuwuddt.com`）
3. 同步显示红点：
   - About 页按钮红点
   - 侧边栏「关于」导航项红点

## 3.5 无更新/失败策略

- 无更新：隐藏红点。
- 检查失败：不阻塞用户、不弹错误拦截框，记录日志即可。

## 5. 实施分阶段

### Phase 1：基础改造

1. 修正 About 页 GitHub 链接。
2. 增加 B站主页链接入口。
3. About 页新增「检查更新」按钮。

### Phase 2：状态与红点

1. 增加更新状态管理（前端内存态）。
2. 接通 About 页按钮红点显示/隐藏。
3. 接通侧栏「关于」导航红点显示/隐藏。

1. 启动后自动检查（异步）。
2. 手动检查触发。
3. 有更新时展示说明弹窗，支持关闭/下载。

### Phase 4：后端接入预留

1. 抽象 `UpdateProvider`。
2. 当前接 `Mock/Static Provider`。
3. 后续替换为 `ServerProvider`（不改 UI 主流程）。

## 6. 验收标准

1. About 页外链正确可点。
2. 应用启动会自动触发一次更新检查（不阻塞 UI）。
3. 手动点击「检查更新」可触发检查流程。
4. 发现更新时：
   - 弹窗出现并显示版本 + 更新说明
   - 按钮红点与侧栏关于红点同时出现
   - 点击下载跳转 `https://wuwuddt.com`
5. 无更新或检查失败时应用稳定，不影响主流程。
